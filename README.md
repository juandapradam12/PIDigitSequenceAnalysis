# Digit Sequence Analysis in $\pi$

A computational case study: count ascending digit sequences in the first $\sim 2.5 \times 10^6$ digits of $\pi$, compare observations against a uniform i.i.d. digit model, and measure how sequential file partitioning affects wall-clock cost.

---

## Use case

Given a long digit expansion of $\pi$, the project answers two concrete questions:

1. **Frequency** — How often do the patterns $1$, $12$, $123$, $1234$, and $12345$ appear?
2. **Throughput under chunking** — How does wall-clock time behave when the same digit stream is processed as $P$ sequential partitions?

Under a uniform independent-digit model, a length-$k$ pattern has match probability $10^{-k}$ at each alignment, so the expected count on $N$ digits is

$$
\mathbb{E}[C_k] = (N - k + 1)\,10^{-k}.
$$

Observed counts are reported next to this baseline (see `results/observed_vs_expected.csv` and `figures/observed_vs_expected.png`).

## Architecture

```
├── include/sequence_counter.h   # Public API
├── src/sequence_counter.c       # Digit load + sliding-window counting
├── src/main.c                   # CLI (patterns, CSV export)
├── scripts/benchmark.sh         # Partition wall-clock study
├── scripts/analyze.py           # Expected-value comparison + figures
├── data/pi_digits.txt           # Input digit stream
├── results/                     # CSV outputs
├── figures/                     # Generated plots
└── docs/methodology.md          # Model, metrics, and design notes
```

| Layer | Responsibility |
| --- | --- |
| **C library** | Load digits, count overlapping substring hits, time each pattern |
| **CLI** | Thin interface over the library; optional CSV export |
| **Benchmark script** | Split the digit file into $P$ chunks; time sequential passes |
| **Python analysis** | Compare observed vs $\mathbb{E}[C_k]$; plot timing curves |

Separation keeps the hot path in portable C, reproducibility in shell, and presentation in Python — without mixing I/O policy into the counting core.

---

## Build & run

```bash
make                    # build bin/pi_counter
make run                # count default patterns → results/pattern_counts.csv
make benchmark          # partition timings → results/partition_benchmark.csv
pip install -r requirements.txt
make analyze            # comparison CSV + figures/
```

Single-file CLI example:

```bash
./bin/pi_counter data/pi_digits.txt --csv results/pattern_counts.csv
./bin/pi_counter data/pi_digits.txt --patterns 7,77,314
```

## Design choices

- **Overlapping matches** are counted (e.g. `11` contributes two hits for pattern `1`), which matches the alignment model behind $\mathbb{E}[C_k]$.
- **Non-digit characters** are stripped on load so decimal points or whitespace cannot bias counts.
- **Partition benchmark** measures sequential chunked I/O + counting, not parallel speedup — the curve isolates per-chunk overhead as $P$ grows.
- **CSV-first outputs** keep the analysis layer replaceable without touching the C core.

Details and formulas: [docs/methodology.md](docs/methodology.md).
